# Salt API: union headword index (A55v2)

Cross-dictionary **union headword index** — one REST endpoint answering *"in
which Cologne dictionaries does this headword exist?"* plus the index's own
metadata (member dictionaries, their versions, headword counts, provenance).
Extension of the published SanskritLexicography union work
([union 15 dicts](https://github.com/gasyoun/SanskritLexicography/blob/master/HeadwordLists/union/UNION.md)
→ [16 dicts](https://github.com/gasyoun/SanskritLexicography/blob/master/HeadwordLists/union-16dicts/UNION16_OVERLAP_REPORT_19-09-2026.md))
to **21 dictionaries**, per ruling D3
([GRILL_RESEARCH_WIDENING 04-10-2026](https://github.com/gasyoun/Uprava/blob/main/reports/GRILL_RESEARCH_WIDENING_04-10-2026.md)):
+MW72, +Apte (`ap90`), PWG per-volume counts, and — while NWS headwords are
not yet on disk (kosha H6064 pipeline output pending) — `lan`, `mwe`, `wil`
to clear the ≥20 bar with real data. NWS is declared `pending` in the meta
and never counted as a member.

## 1. Endpoints

### 1.1. Index meta (no `key`)

```
https://www.sanskrit-lexicon.uni-koeln.de/scans/awork/apidev/api1/salt_union.php
```

Returns the `union_meta.json` envelope: `index_version`, `n_dicts`,
`n_union_headwords`, `members[]` (code / title / `version` (CDSL year) /
`headwords` / `source` / residue counts; `pwg` additionally carries
`volumes` — per-Teil headword counts from `<pc>` vol-page keys),
`pending[]` (NWS), normalization contract, provenance (csl-orig commit +
sha256 per source).

### 1.2. Union lookup

```
.../api1/salt_union.php?key=aNga
```

| parameter | example | notes |
|---|---|---|
| key | aNga | Headword in the `input` scheme. Required for lookup mode. |
| input | deva | `slp1` (default), `deva`, `hk`, `roman`, `itrans`, `velthuis`. Unknown schemes fall back to `slp1` (Parm convention). |
| output | deva | Optional output scheme: adds `headword_output`. |
| callback | cb1 | JSONP (shared whitelist guard, H4212). |

Response (200):

```json
{"status":200,"key":"aNga","headword_slp1":"aNga","n_dicts":19,
 "dicts":["ap","bhs","bur","cae","ccs","gra","inm","lan","md","mw","mw72",
          "pd","pw","pwg","sch","skd","vcp","vei","wil"]}
```

Errors: `400` invalid/empty key; `404` headword not in union
(`{"status":404,"error":"headword not in union index","key":...}`);
`500` data files missing/corrupt (truthful failure, H3636 semantics).

## 2. Data contract

- `api1/data/union_headwords.tsv` — `slp1 \t n_dicts \t code,code,...`,
  **byte-sorted** (UTF-8 codepoint — the internal binary-search order,
  *not* varṇa-krama display order).
- `api1/data/union_meta.json` — the meta envelope, served verbatim.
- Regenerated by `tools/build_union_index.py` from live `csl-orig/v02`
  (PD from the committed now-2026 exports — it has no csl-orig source).
- Key normalization = the H4797 union contract: parentheticals stripped
  whole; marks `/ ˚ * ' ^ | - – — ‐` removed; residue (leading `(`/digit,
  leftover mark, non-ASCII-letter) counted per class and **excluded**.
  Membership per dict = `norm(k1) ∪ norm(k2)`.
- No `*.sqlite` dependency: the endpoint is self-contained on the two
  committed data files; lookups are `fseek` binary searches.

## 3. Consumer smoke

`python3 tools/union_consumer_smoke.py` boots the PHP built-in server and
asserts: meta ≥ 20 dicts with versions; `aNga` ≥ 15 dicts; 404 envelope;
deva round trip; JSONP faces. Prints `CONSUMER-SMOKE: GREEN|RED`.
